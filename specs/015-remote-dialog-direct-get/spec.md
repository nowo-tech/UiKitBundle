# Feature Specification: Remote dialog content opened directly

**Feature Branch**: `feat/remote-dialog-direct-get`  
**Created**: 2026-11-24  
**Status**: Implemented (target 2.73.0)  
**Input**: Owner request relayed by Beacon (D-20261124-05), 2026-11-24: a remote-dialog content URL opened in the
address bar (example: CrmKit's `/customers/import/hubspot/connect`) renders a bare fragment page; it should land on its
owning page with that dialog open on that step. Part 2 of the request: the generic UiKit contract, so CrmKit (part 1,
a later CrmKit release) and other on-demand dialogs adopt it by configuration.

## Summary

`nowo_ui_kit.remote_dialog.direct_get.routes` marks routes as dialog content (route name → owning page route, dialog
id, `page_parameters`, `redirect_same_origin`). A top-level navigation to such a route is answered with a `302` to the
owning page plus a reopen query (`_dialog[route]`, `_dialog[params]`); the owning page's `remote_form_dialog` partial
prints the dialog's safe list and the target the router generated again, and both runtimes open the dialog there and
clean the URL. Off by default, opt-in per route.

## User scenarios

- **US-1 (address bar)** — Given a marked route `crm_import_mapping` owned by `crm_import` / `crm-import-dialog`, when a
  user pastes `/import/42/mapping` in the address bar, then the browser lands on `/import` with the dialog open on the
  mapping step of import 42, and the address bar shows `/import`.
- **US-2 (denied)** — Given the user may not see import 42, when they open its URL directly, then they get the 404 (or
  403) the controller answers, never the redirect.
- **US-3 (forged reopen)** — Given a link `/import?_dialog[route]=admin_delete`, when it is opened, then no dialog opens
  (the route is not in the dialog's safe list) and no URL from the query is ever fetched.
- **US-4 (no JavaScript)** — Given a page link to a marked route followed without JavaScript, then the route's own page
  is shown (the no-JS fallback), unless the route sets `redirect_same_origin`.
- **US-5 (dialog fetch, POST)** — Given the dialog itself loads or posts the URL, then the fragment, the `422` re-render
  and the `204` answers are unchanged.

## Requirements

- **FR-DIRECTGET-001 (marking)** — `remote_dialog.direct_get`: `query_parameter` (`_dialog`; letters, digits, `_`) and
  `routes` (empty). Each entry: `page` and `dialog` required, `page_parameters` (`[]`), `redirect_same_origin`
  (`false`). Route names `[A-Za-z0-9_.-]`, a dialog id starting with a letter, parameter names `[A-Za-z_][A-Za-z0-9_]*`,
  and a route cannot own itself; an owning page cannot itself be a marked route (no redirect loop or chain); anything
  else fails the container build. Kits prepend their routes; a host entry replaces a kit's entry whole, and
  `<route>: false` (or `enabled: false`) unmarks it. With no route the listener is not registered and the partial prints nothing new.
- **FR-DIRECTGET-002 (redirect)** — `RemoteDialogDirectGetListener` (`kernel.response`, priority -5) converts only a
  main `GET` / `HEAD` request of a marked route answered `200` with an HTML or untyped body, that is a top-level
  navigation: no dialog request header, no `X-Requested-With: XMLHttpRequest`, no `Turbo-Frame`, `Sec-Fetch-Mode:
  navigate` and `Sec-Fetch-Dest: document` (or none); and not `Sec-Fetch-Site: same-origin` unless
  `redirect_same_origin`. Without `Sec-Fetch-Mode` nothing changes. The `302` target is the owning page generated by the
  router with the page parameters and `_dialog[route]` + `_dialog[params]` (the route parameters and scalar query values
  of the request, all carried whole: a nested value, one over 512 characters or more than 32 values cancel the
  redirect); it must be a same-origin path, else nothing changes. Marked routes must be safe GETs (the controller runs
  twice on a direct GET) and are never ESI-included. Cookies are kept, `Cache-Control: no-store,
  private`; every answer of a marked route varies on the dialog header and `Sec-Fetch-Mode` / `-Dest` / `-Site`.
- **FR-DIRECTGET-003 (access first)** — The conversion runs after the firewall and the controller: a denied request
  (`401`, `403`, `404`, login redirect) is never converted. POSTs, `422` re-renders, dialog fetches, non-HTML answers
  and unmarked routes are unchanged.
- **FR-DIRECTGET-004 (owning page)** — `nowo_ui_remote_dialog_reopen_attrs(id)` (merged by the `remote_form_dialog`
  partial) prints, for a dialog with marked routes on the current route, `data-nowo-ui-remote-form-reopen-param` and
  `-reopen-routes` (safe list), and for a reopen query naming a safe-listed route, `-reopen-route` and `-reopen-url`:
  the URL regenerated by the router from the route name and at most 32 scalar parameters (≤ 512 characters each),
  checked same-origin. A foreign or unknown route, rejected or nested parameters print no target.
- **FR-DIRECTGET-005 (client)** — Both runtimes (`js/nowo-ui-dialog.js` once the document is parsed, the
  `remote-form-dialog` peer on connect; the IIFE runtime leaves a peer-driven dialog to the peer) open the dialog once
  when the page query names a route that is in the safe list and equals `-reopen-route`, and `-reopen-url` passes
  `sameOriginPath()`. After it opens, the reopen parameter (`_dialog`, `_dialog[…]`) is removed with
  `history.replaceState` (state kept). A failed load shows the dialog's alert and never follows the dialog URL.

## Success criteria

- **SC-1** — PHP: direct GET → `302` per marked route with its parameters; dialog fetch / no metadata / iframe / XHR /
  Turbo frame / CORS / same-origin link → fragment; `403` / `404` without `Location`; POST and `422` unchanged; unmarked
  route unchanged; foreign, unknown, rejected or nested reopen queries print no target
  (`tests/Integration/RemoteDialogDirectGetKernelTest.php`, `tests/Unit/Dialog/RemoteDialogContentTest.php`); line
  coverage stays 100 %.
- **SC-2** — Vitest: safe-list rejection, same-origin target, history clean-up, both runtimes
  (`nowo-ui-remote-dialog-reopen.test.ts`).
- **SC-3** — Demo e2e (`demo/symfony8/e2e/tests/remote-dialog-direct-get.spec.ts`): `/kit/remote-form/new` and
  `/kit/remote-form/wizard/channel?label=Ops` opened directly land on `/kit/remote-form` with the dialog on that step and
  a clean URL; a foreign reopen query opens nothing; the no-JS link keeps the full page.

## Non-goals

- Reopening a plain `data-nowo-ui-dialog-src` dialog or a Bootstrap modal (only the remote form dialog).
- A route attribute or option as the marker: the configuration map is the single, enumerable source of the safe list
  (route defaults are not visible to the owning page without loading the whole route collection).
- Carrying non-scalar query values of the dialog URL.

## Validation

`make test`, `make test-ts`, `make phpstan`, `make cs-check`, and in `demo/symfony8`:
`npx playwright test --project=chromium tests/remote-dialog-direct-get.spec.ts`.
